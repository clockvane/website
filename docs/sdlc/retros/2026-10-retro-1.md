# Build-phase retro 1 (2026-10-30)

Scope: the last 30 merged PRs (#48 to #95, 2026-10-26 to 2026-10-30) and open PR #93. Review counts are the number of review comments on each PR (a proxy for loops).

## What slowed us down
- **Owner redesign mid-build.** The change request (#77, #81, #83) led to ADR-004 (#82), three concepts (#85), a copy deck (#89) and design system v2 (#91, #86). The pages built earlier (#72, #73, #74, #76) now need migrating, which is the work in #88.
- **Waiting on owner merges.** Infra and workflow PRs sat open until he merged them: #52 (about 13 h), #66 (about 32 h), #85 (about 3 h), #73 and #74 (about 12 h). Fast docs PRs merged in minutes (#89, #91).
- **Kit upgrades** (#53, #67, #68, #84, #90, #92, #95) are frequent but cheap; they add noise, not delay.

## Review loops
- **#93 (issue #88) hit 3 rounds** (7 reviews as of this writing):
  - Rounds 1 and 2: QA requested changes only because AC5 required Lighthouse scores and per-page sizes that nobody could produce.
  - Round 3: the tech lead found `assetsInlineLimit: 0` (ADR-004 section 7) missing. Without it the motion controller would be inlined and blocked by CSP.
- **#66 (contact form, 12 reviews):** the UX designer requested changes in round 1, then all seven roles re-approved the next commit. The full panel re-review was costly.
- **#74 (8 reviews), #73 and #69 (5 each):** one round each, no change requests.
- No merged PR had a formal CHANGES_REQUESTED review state (verdicts are in comment bodies).

## CI
Of the last 40 workflow runs, 23 succeeded, 8 failed and 9 were skipped. All 8 failures were the `deploy-preview` workflow on `main` (for example runs 40985044896 and 40923670548). Likely cause is a missing Cloudflare secret or project, which is an owner step; the preview deploy for PRs (#48) otherwise works. Needs a look, but it is not flakiness in the test jobs.

Lighthouse cannot run in the WSL agent environment ("Unable to connect to Chrome") and has no PR CI job, which caused the #93 loop.

## Usage hotspots
- Multi-role re-review of every new commit (#66 with 12 reviews, #74 with 8).
- Design-system re-work after the redesign (#85, #91).
- Repeated QA runs that could not produce evidence (#93).

## Proposed process changes
1. #97: run Lighthouse in CI on PRs and post scores, so tickets cite CI evidence.
2. #98: ADR checklist in the self-review of `arch-impact` PRs, with binding ADR clauses quoted in acceptance criteria.

Follow-up for the owner: check the `deploy-preview` failures on `main` (secrets or project config).
