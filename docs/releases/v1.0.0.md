## Defaults the owner approves at Gate 3
Recommended defaults (#198, owner's lead request 2026-11-11). Merging the `gate:3` PR approves them as written; to change one,
comment on that PR. This is not legal advice: a qualified review of the privacy notice is still recommended (PRD Q9).

- **Q19 how a session works:** after you book, we confirm the expert, the time and the format (a video call) by email. `/how-we-work/`, "If you need an expert".
- **Q9 operator identity:** brand and email from `site.config.ts`, based in Telangana, India; no street address or registration number. `/privacy/`, "Who we are".
- **Q9 purpose:** only to answer the enquiry and arrange the requested work; no marketing or newsletters; never sold or shared for advertising. `/privacy/`, "Why we use it".
- **Q9 retention:** enquiries kept up to 24 months after the last contact, then deleted; sooner on request. `/privacy/`, "How long we keep it".
- **Q9 rights:** email us to see, correct or delete your details; we reply within 30 days. `/privacy/`, "Questions about your information".
- **Recipients and transfers:** HubSpot (CRM, US data centre) and Cloudflare (hosting, form handler) process the data for us; the notice says only that each publishes data processing terms using standard contractual clauses ([HubSpot DPA](https://legal.hubspot.com/dpa), [Cloudflare DPA](https://www.cloudflare.com/cloudflare-customer-dpa/)). Neither page confirms it applies to free accounts without acceptance, so the owner checks this in each account ([Owner checklist #164](https://github.com/clockvane/website/issues/164)). `/privacy/`, "Who receives it".
- **Technical logs and spam prevention:** honeypot and timing check (not stored), per-IP rate limit at the Worker (IP used only for that check), Worker logging off, Cloudflare's own edge logs. `/privacy/`, "What we collect".
- **Publication date:** one constant, `PRIVACY_UPDATED` in `src/content/privacy.ts`, set to 11 November 2026; the release PR moves it if the notice text changes again. `/privacy/`, "Last updated".

The PRD's open Q4 line ("supply the public Meetings URL") is out of date: `booking` is already set in `site.config.ts` (#179).

**Config values** (`site.config.ts`, not rendered as markers): `phone` (optional, PRD Q8 deferred it), `socials.linkedin`

## Rollout and rollback
Merging the `gate:3` PR approves the release. The release PR adds `CHANGELOG.md` and the `v1.0.0` tag. `release.yml` then
waits in the `production` environment until the owner clicks **Approve and deploy**. It deploys the same checksum-verified
`main` artifact that staging tested, then smoke-tests production and the Worker `/health` route. For this first release
there is no earlier production deployment to roll back to. The fallback is Cloudflare Pages "Rollback to this deployment",
or fixing forward with `v1.0.1`. Steps: [release.md § First go-live](../devops/release.md#first-go-live-v100).
